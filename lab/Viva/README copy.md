# Simple CMS

Blog Content Management System for the Backend Development Lab Examination.
Stack (Option A): Node.js, Express.js, EJS templates, MongoDB Node.js driver.

Each post has a title, content, author and a `createdAt` date that the server sets automatically.

## Setup and run
1. Install Node.js 18 or newer and start MongoDB on `mongodb://127.0.0.1:27017`.
2. Open this folder in VS Code and run these commands in the terminal:
```
npm install
npm start
```
3. Open http://localhost:3000 in a browser. (`npm run dev` restarts the server when files change.)

Database: `cms_lab`, collection: `posts`. Both are created automatically on the first post.

## Routes
| Method | Route        | Purpose                                              |
| ------ | ------------ | ---------------------------------------------------- |
| GET    | / or /posts  | List all posts (title link, author, date; no content) |
| GET    | /posts/new   | Create-post form                                     |
| POST   | /posts       | Validate, insert with `createdAt`, redirect to /posts |
| GET    | /posts/:id   | Full post, fetched from MongoDB by `_id`             |

## Files
- `app.js`: server, MongoDB connection and routes
- `views/posts.ejs`, `views/new-post.ejs`, `views/post.ejs`: the three page templates
- `views/partials/`: shared header and footer
- `public/style.css`: styling

# Simple CMS

A Blog Content Management System built for the Backend Development Lab Examination.
Stack: **Node.js, Express.js, EJS, MongoDB Node.js Driver** (Option A from the exam sheet).

Users can write a post, see every post listed on the home page, and open any post's
full content on its own page. Everything is rendered server-side and stored
permanently in MongoDB.

## Challenges faced and how they were solved

**1. Route order: `/posts/new` vs. `/posts/:id`**
Express matches routes top to bottom. With the dynamic route declared first, a request
for `/posts/new` would match it with `id = "new"` and try to build `new ObjectId("new")`,
which throws. Fixed by declaring the static `/posts/new` route before the dynamic
`/posts/:id` route.

**2. Untrusted `:id` values crashing the server**
`new ObjectId(id)` throws if `id` isn't a valid 24-character hex string, and users can
type anything into the URL. Solved by checking the id against `/^[0-9a-f]{24}$/i` first
and returning a 404 instead of letting the error reach MongoDB.

**3. Requests arriving before MongoDB finished connecting**
Calling `connectDB()` without waiting for it (as in the exam's own hint code) leaves a
window where `postsCollection` is still `undefined` if a request lands immediately after
startup. Solved by wrapping startup in an `async start()` function that awaits
`client.connect()` and only calls `app.listen()` after the collection is ready.

**4. Keeping full post content out of the list page**
The brief specifically says the list page must not send the full content. A plain
`find()` returns every field. Solved with a projection, `{ content: 0 }`, so MongoDB
itself excludes the field from the query result.

**5. Preventing stored content from breaking the page (XSS)**
EJS's `<%= %>` escapes HTML automatically, but the shared header/footer partials are
included with `<%- include(...) %>`, which prints raw HTML. Had to be deliberate about
which tag goes where: `<%- %>` only for trusted partials, `<%= %>` for every field that
came from user input (title, author, content).

**6. Duplicate posts on refresh**
Rendering a response directly from the POST handler means pressing refresh resubmits the
form and creates a second identical post. Solved with the Post/Redirect/Get pattern —
`res.redirect('/posts')` after a successful insert, so the browser's last request is a
harmless GET.

**7. Validating on the server, not just the browser**
Browser `required` attributes are easy to bypass (dev tools, curl, Postman), and the
brief asks for server-side validation. Solved by adding `novalidate` to the form so
blank submissions actually reach the server, then trimming and checking each field
there — a field of only spaces is treated as empty.

**8. Stray whitespace-only or object-shaped form fields**
With `express.urlencoded({ extended: true })`, a crafted field name like `title[$ne]=x`
arrives as an object instead of a string, which could otherwise reach a MongoDB query.
Solved by wrapping every field in `String(...)` before validating or storing it.

**9. Reusing the header and footer without a native layout system**
EJS has no built-in "layout" concept like some other engines. Solved by splitting a
common header and footer into `views/partials/` and pulling them into each page with
`include()`, instead of duplicating the `<head>` and navigation in three files.

**10. Formatting dates consistently across pages**
`createdAt` is stored as a BSON `Date` (UTC), but it needs to display readably in
several templates. Solved by registering one `formatDate` helper on `app.locals`, so
every view formats dates the same way without repeating the logic.

## Known limitations

- No editing or deleting a post.
- No authentication — any visitor can publish under any author name.
- No CSRF protection or rate limiting on the form.
- No length limit on title or content.

## Possible improvements

- Add `PUT /posts/:id` (or a POST-based override) to edit posts, and a delete route.
- Add pagination (`limit`/`skip`, or range-based paging on `createdAt`) once the post count grows.
- Add an index on `createdAt` to keep the sort fast at scale.
- Add basic auth so `author` reflects a logged-in user rather than free text.
